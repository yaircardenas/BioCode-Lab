# Teacher Guide

BioCode Lab can be used as a standalone classroom activity. Students do not
need accounts, installs, notebooks, or a shared server.

## Before Class

1. Open the public site and test it on the same kind of device students will
   use:

   https://yaircardenas.github.io/BioCode-Lab/

2. Decide which path students should use:
   - **Guided Path** for a first run, because missions unlock in sequence.
   - **Free Explore** for review sessions, workshops, or mixed-experience
     groups.

3. If you want a class code, ask students to open the class option and enter
   the same code. This is stored locally in their browser and appears in
   exported `.biocode` files.

4. Tell students to choose an alias that you can recognize if you plan to
   collect progress files. Avoid asking for private identifiers unless your
   institution requires them.

## During Class

Students should start with **Start the course**, choose a path, and open a
mission from the map.

Useful live prompts:

- Ask students to run code before checking when they are debugging.
- Ask them to use hints only after explaining what they think is happening.
- For terminal missions, have them read the current folder, file tree, command,
  and output before trying another command.
- If the Python engine is still loading, wait for the ready message before
  starting code-heavy missions.

## Collecting Progress

Students can download their progress with **Export progress**. The file ends in
`.biocode` and includes:

- alias and class code;
- XP, completed missions, levels, and badges;
- attempts, hints, and completed challenges;
- final code and output for completed or attempted work.

To continue later, students can use **Import previous progress (.biocode)**.
Importing replaces the progress currently stored in that browser.

## Teacher Dashboard

Use **Teacher dashboard** to load many `.biocode` files at once. The dashboard
runs locally in your browser and summarizes:

- number of students loaded;
- average XP and average completed missions;
- total runs and hints;
- mission completion;
- hardest challenge by completion and attempts;
- XP leaderboard.

Nothing is uploaded by the dashboard. It reads the files you select and builds
the summary in the browser.

## Learner Survey

The **Survey** button is in the top navigation next to **Profile**. It sends
answers to the connected Google Form and does not save survey answers in the
student's browser or in `.biocode` files.

Current survey questions:

- education level;
- country;
- learning level from 0 to 5;
- difficulty from 0 to 5;
- tediousness from 0 to 5;
- recommendation from 0 to 5;
- optional comment.

Use the Google Forms **Responses** tab to review results or export them to a
spreadsheet.

## After Class

Recommended follow-up:

1. Export Google Forms survey results.
2. Collect `.biocode` files from students who agree to share progress.
3. Load the `.biocode` files into the Teacher Dashboard.
4. Compare the dashboard with survey results:
   - high difficulty plus many attempts usually means a concept needs a better
     explanation;
   - high tediousness plus low learning may indicate an activity should be
     shortened;
   - low recommendation with high difficulty can point to friction rather than
     lack of value.

## Privacy Notes

BioCode Lab does not require student accounts. Learning progress is stored in
the student's browser unless exported. The survey is optional and goes to the
connected Google Form. The public site also uses privacy-first aggregate Umami
analytics for broad usage signals, not individual student tracking.
