# BioCode Lab v1.0.2

**Learn Python. Decode Biology.**

BioCode Lab is a bilingual, gamified learning environment for biology students
who are starting from zero. It teaches Python and introductory bioinformatics
through biological missions instead of disconnected toy examples.

## What students learn

The course contains 17 missions in three parts:

- **Python foundations (missions 1-9):** variables, strings, numbers,
  `input()`, `int()`, lists, dictionaries, indexing, slicing with square
  brackets (`[]`), conditions, loops, functions and debugging.
- **Terminal foundations (missions 10-12):** paths, `pwd`, `ls`, `cd`,
  `mkdir`, copy/move/remove, file inspection, search, pipes, redirection,
  command history and running Python scripts.
- **Bioinformatics toolkit (missions 13-17):** imports, `Counter`, FASTA
  files, `sys.argv`, `pathlib`, error handling and Biopython with `Seq` and
  `SeqIO`.

The final missions combine Python, terminal commands, FASTA data and
Biopython into practical sequence-analysis workflows.

## Learning experience

Students can choose between:

- **Guided Path:** missions unlock in sequence.
- **Free Explore:** all missions are available for review in any order.

Each mission mixes short explanations, worked examples, prediction checks,
code-writing, debugging, drag-and-drop Parsons exercises and personalized Boss
Challenges. Hints and verified solutions provide a way forward when a learner
gets stuck.

The app also includes:

- English and Spanish interface and explanations;
- alias and laboratory avatar for a personal learner identity;
- XP, levels, badges and a local learning history;
- a virtual terminal with Linux/macOS and Windows PowerShell views;
- a task panel inside the terminal, file-tree feedback and color-coded
  commands, output and status messages;
- an essential-command reference embedded directly in the terminal;
- safe handling for common infinite `while` loops and excessive output;
- optional FASTA upload kept locally in the current session;
- progress export/import as a `.biocode` file;
- PDF learning evidence generated by the app;
- achievement cards and optional social sharing;
- an optional local Teacher Dashboard for imported `.biocode` files;
- a local learning-statistics dashboard and an optional anonymous survey;
- privacy-first aggregate usage measurement with Umami.

## Privacy and storage

No account is required. Progress, code, aliases and settings stay in the
browser's local storage unless the learner deliberately exports a `.biocode`
file or chooses to share an achievement card. Uploaded FASTA text is kept
locally for the current learning session.

The published GitHub Pages site uses Umami Cloud to measure anonymous visits
and educational milestones such as course starts, missions opened, program
runs, completed challenges and completed missions. The tracker is restricted
to `yaircardenas.github.io` and respects the browser's Do Not Track setting.

The optional survey sends only its closed-choice answers, the interface
language, learning path and completion totals. The free-text comment remains
on the learner's device and is included only if the learner downloads the
local anonymous report. BioCode Lab never sends the learner's alias, source
code, terminal commands, biological sequences or class code to Umami. If a
browser or content blocker prevents analytics, the learning app still works.

## Runtime requirements

The complete application is one file: `index.html`.

Python execution uses Pyodide from a pinned CDN release, and QR achievement
cards use QRCode.js from a pinned CDN release. Biopython is installed inside
Pyodide when its missions are opened. Internet access is therefore required
for the Python runtime and Biopython missions; nothing needs to be installed
on the learner's computer.

The app runs in a current desktop or mobile browser. Hosting it over HTTPS is
recommended for QR sharing and the browser's native share features.

## Run locally

Open `index.html` in a current browser, or serve this folder with any simple
local HTTP server. The app does not require a build step, database or server
application.

## Publish with GitHub Pages

This repository is ready to publish from its root folder:

1. Open **Settings → Pages** in the GitHub repository.
2. Choose **Deploy from a branch**.
3. Select branch `main` and folder `/ (root)`.
4. Save and open the URL GitHub provides.

Because the application is named `index.html`, GitHub Pages opens it
automatically at the repository URL.
